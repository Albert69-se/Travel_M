## Audit findings

- Data integrity: `isValidIsoDate()` accepted calendar rollover dates such as
  February 30; `validateExpense()` accepted tiny positive inputs which would
  round to stored zero. Both fixed with additional automated coverage.
- Maps: existing Leaflet/OSM map was functional, though Leaflet CDN resources
  lacked integrity attributes; SHA-384 integrity was added.
- React UI: the MapPanel had an unused import, removed.
- Information accuracy: 12,389 records from OpenStreetMap are labeled
  `imported`, not verified; these do **not** replace curated source-checked
  destination facts required by FR-3/NFR-9.
- Accounts: browser localStorage only; not cross-device persistence or
  production-enforced authentication. Data migration/backups and a backend
  remain major architectural gaps.
- Three preexisting lint warnings remain: two Fast Refresh warnings in the
  store module, one synchronous state update in Discover's filter effect.
- Google Maps Demo Key supports testing and evaluation only. A later explicitly
  requested hosted course-evaluation deployment was performed. Production
  deployment without a properly licensed key remains blocked by the script.

## Implemented

- React-only optional Google Maps JavaScript API adapter using
  `VITE_GOOGLE_MAPS_DEMO_KEY` in gitignored `.env.local`.
- Advanced markers with a 200-pin sampling cap for all-country results.
- OpenStreetMap fallback and keyless official Google Maps view/directions links.
- Strict date validation and minimum persisted expense precision.
- Leaflet CDN subresource integrity.
- Added browser smoke test `scripts/google-demo-smoke.py`.
